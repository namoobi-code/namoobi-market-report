# namoobi-sub-plan (v1.0)

청약 탭의 **'예정' 칩**이 렌더하는 분양예정 목록을 주 1회 최신 유지한다.
공고가 뜸한 지역(성남·판교)에서 "언제 뭐가 나올지"를 미리 보는 것이 목적 —
이사 지역·거주요건(서울 2년 / 경기 1년) 결정에 직결되므로 **시기 정확도가 최우선**이다.

## 왜 LLM 리서치인가

청약홈·data.go.kr 어디에도 **분양예정 API 가 없다**(2026-09 실측: ApplyhomeInfoDetailSvc·
ApplyhomeInfoCmpetRtSvc 전 엔드포인트 확인 — 전부 공고 이후 데이터). 예정 정보는
언론 보도·지자체 정비구역 고시·조합 공지에 흩어져 있어 웹 리서치로만 모을 수 있다.

## 산출물

`data/db/applyhome_plan.json` — 청약 탭 '예정' 모드가 렌더하는 정본.
**스키마 고정** (프론트 파싱 — 필드 삭제·개명 금지):

```json
{"asof":"YYYY-MM-DD HH:MM","src":"...","note":"...",
 "regions":["서울","경기"], "bands":["임박","2027","2028+","미정"],
 "items":[
  {"name":"사업명","reg":"서울|경기","sgg":"○○구|성남시 ○○구","addr":"위치",
   "typ":"민영|국민|미정","kind":"재개발|재건축|리모델링|공공택지|신도시",
   "total":1149,"gen":143,"when":"2026-09|2027 상반기|2028 이후|미확정",
   "stage":"조합설립|사업시행인가|관리처분|착공|분양승인","price":"평당/억 문자열|null",
   "note":"특이사항·지연 리스크·수치 불일치 병기","src":"출처URL","srcname":"매체명",
   "asof":"보도일 YYYY-MM-DD","wk":202609,"band":"임박"}]}
```

- `wk` = 정렬키(YYYYMM). `when` 파싱 결과이며 미상은 999998, 미확정은 999999.
- `band` = 시기 구간 칩. 오늘+6개월 이내면 `임박`, 2027년이면 `2027`, 이후는 `2028+`.
- **`src`·`asof` 는 필수** — 보도 기반이라 출처 없는 행은 신뢰할 수 없다. 없으면 담지 않는다.

## 워크플로우

### Phase 0 — 현황 로드

```bash
curl -s https://namoobi.duckdns.org/api/db/applyhome_plan | python3 -m json.tool | head -40
curl -s https://namoobi.duckdns.org/api/db/applyhome_sub  # 공고가 난 단지 — 중복 제거용
```

### Phase 1 — 정밀조사 (WebSearch · 서브에이전트 2개 병렬)

> ⚠️ 서브에이전트에겐 **조사 결과 JSON 파일만** 요구한다. "서버 업로드·정본 수정 금지"를
> 프롬프트에 명시할 것 — 각자 업로드하면 서로 덮어써 정본이 깨진다(run-search 에서 실측).
> 병합·업로드는 오케스트레이터가 단독 수행한다.

- **에이전트 A — 성남권**: 성남 수정·중원 원도심 재개발(신흥·태평·상대원·수진·금광),
  분당 1기 신도시 재건축(선도지구 4곳·2차 공모), 판교 금토2·여수2·서현 신규택지,
  리모델링(느티마을·한솔 등), 용인 수지·광주시 인접 생활권.
- **에이전트 B — 서울**: 강남권 재건축(반포·개포·잠원·방배), 강북·서남 재개발
  (한남·노량진·흑석·갈현·이문휘경·장위·신월곡), 연내 분양 예정 단지.

각 에이전트 프롬프트에 반드시 넣을 것:
- "추측 금지 — 기사·고시에 실제로 적힌 것만. 불확실하면 note 에 '추정'·'미확정' 명시"
- "출처 URL·매체명·보도일(asof)을 행마다 필수 기재"
- "이미 입주자모집공고가 난 단지는 제외"(Phase 0 의 applyhome_sub 목록과 대조)
- "총세대·일반분양 수치가 출처마다 다르면 note 에 병기"

### Phase 2 — 병합·정규화 (오케스트레이터 단독)

1. 두 결과를 합치고 `reg`/`sgg` 정규화(서울 → `reg:서울`, 그 외 → `reg:경기`).
2. `when` → `wk`·`band` 계산.
3. **정본 대조**: 기존 항목 중
   - 공고가 난 단지(applyhome_sub 에 등장) → **제거**(이제 '완료/모집중' 표에 나온다)
   - 이번 조사에서 사라진 항목 → 함부로 지우지 말고 유지하되, 최신 보도가 없으면
     note 에 "최근 갱신 없음(YYYY-MM 기준)" 추가
   - 일정이 밀린 항목 → `when`·`asof` 갱신하고 note 에 지연 사유 기록
4. `wk` 오름차순 → 일반분양 세대 내림차순 정렬.

### Phase 3 — 업로드·검증

```bash
mkdir -p ~/.nmr && cp <연결폴더>/SECURITY/nmr_deploy_key ~/.nmr/key && chmod 600 ~/.nmr/key
scp -i ~/.nmr/key -o StrictHostKeyChecking=no applyhome_plan.json \
    ubuntu@161.33.190.254:namoobi/data/db/applyhome_plan.json
curl -s https://namoobi.duckdns.org/api/db/applyhome_plan | \
  python3 -c "import json,sys; d=json.load(sys.stdin); print('OK', d['asof'], len(d['items']),'건')"
```

로컬 저장소(`namoobi-market-report-server/data/db/`)에도 동일 저장 후 `gitsync.sh` 커밋.

### Phase 4 — 결과 보고

신규 편입 N건(이름) · 공고 전환돼 제외 N건 · 일정 지연 N건 · **임박(6개월 내) 목록**을
3~5줄로 요약. 성남·판교에 임박 물량이 생겼으면 반드시 앞세워 보고한다(사용자 관심 1순위).

## 정책 이벤트 체크 (매회)

분양예정은 **정부 공급대책**에 크게 흔들린다. 매 실행마다 아래를 확인해 반영한다.

- **8.13 대책(2026-08-13 · 수도권 23만가구+α)** 후속: 나머지 **7.3만가구 신규택지 후보지**가
  9월말~10월초 발표 예정 → 발표되면 개별 지구로 쪼개 편입하고 '후보지 발표 대기' 항목은 제거한다.
  서울 그린벨트(내곡·세곡·자곡·수서차량기지·방이동)와 용산공원 포함 여부가 최대 관심사
  (2026-08-26 기준 **제외 가능성** 보도).
- **토지거래허가구역** 지정·해제: 매수 시 실거주 의무가 붙어 사용자 의사결정에 직결된다.
  현재 강서·남양주·광주 49.41㎢(2031-08-17까지), 서울·인접 그린벨트 503.82㎢(연말까지 한시).
- **착공 단축 모델**: 공공택지 발표→착공을 68개월 → 37개월로 줄이는 게 정부 목표.
  기존 3기 신도시 사례로 일정을 추정할 때 이 단축분을 감안하되, **실적이 확인되기 전까지는
  보수적으로** 본다.
- 1기 신도시 특별법(분당 선도지구) 후속 공모, 정비사업 규제 완화도 함께 확인.

## 주의

- **일정은 지연 편향으로 읽는다.** 서울 정비사업 336곳 중 실제 공사 중은 32곳
  (한국경제 2026-08-10). 착공 시점만 보도된 건은 `when` 을 지어내지 말고 `null`+note 처리.
- 조합 갈등·시공사 교체·이주 지연은 **일정이 수년 밀리는 주된 사유** — 발견하면 note 에 명시
  (실측: 성남 상대원2구역 시공사 DL→GS 교체로 3~5년 지연 가능성 보도).
- 사업명이 같아도 **별개 구역**인 경우가 있다(실측: 성남 산성구역 vs 산성역 헤리스톤).
