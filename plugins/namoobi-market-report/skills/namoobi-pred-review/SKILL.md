# namoobi-pred-review (v1.0)

Portfolio 탭 예측모델(stlead)의 **실전 성적 원인검토** 워크플로우. 검증 루프의 4단계:

```
① 스냅샷 적재(매일 05:20, stlead.py) → ② 채점(매월 1일 06:40, stlead_score.py)
→ ③ 이탈 판정(고정 기준, 채점에 포함) → ④ 원인검토·보완 제안 ← 이 스킬
```

핵심 원칙:
- **제안까지만** — 성적이 나쁘다고 모델을 자동 수정하지 않는다(과최적화 방지).
  보완은 사람이 리포트를 보고 결정한다.
- **원인 3분류** — (a) 데이터 문제(수집 오류·지표 단절), (b) 레짐 변화(금리·정책 전환으로
  과거 상관 무효화), (c) 모델 한계(고변동 자산·표본 부족). 분류가 달라야 처방이 다르다.
- **결측은 결측으로** — 원인을 특정할 수 없으면 "특정 불가"로 쓴다. 지어내기 금지.

## 워크플로우

### Phase 1 — 성적 확인
`https://namoobi.duckdns.org/api/db/stlead_score` 를 가져온다.
- `flagged` 가 비어 있으면: `{"asof": 오늘, "summary": "이탈 없음 — 전 자산 기준 내 작동", "items": []}` 로 리뷰 파일을 만들고 Phase 4로 간다.
- `scored`(채점 수)가 0이면: 표본 미축적 상태 — 리뷰 생략, 그대로 종료해도 된다.

### Phase 2 — 이탈 자산별 원인 검토 (flagged 각각)
`https://namoobi.duckdns.org/api/db/stlead` 의 해당 자산(targets[tk])에서:
1. **어긋난 예측 복원**: score의 `by_h[h].recent` (m0·pred·act) — 언제 한 어떤 예측이 얼마나 어긋났나.
2. **지표 기여도 점검**: `pred[h].cont`(지표별 기여)·`beta` — 틀린 방향으로 크게 기여한 지표 상위 2~3개 특정.
3. **데이터 점검**: `series`에서 그 지표의 최근 값이 단절·급변·결측인지 확인(수집 오류 의심).
4. **레짐 점검**: 웹 검색으로 해당 기간 거시 이벤트(금리 전환·정책·전쟁 등) 확인 —
   지표-자산의 과거 상관이 구조적으로 깨졌을 만한 사건이 있었는가.
5. **분류·처방 제안**: (a)면 수집 스크립트 수정 제안, (b)면 해당 지표 가중치 하향 또는
   표본 구간 단축 제안, (c)면 "⚠ 신뢰불가 표시 유지" 제안. 시차 재탐색·지표 교체는
   구체 근거가 있을 때만 제안한다.

### Phase 3 — 리뷰 파일 생성
```json
{"asof": "YYYY-MM-DD", "summary": "한 줄 총평",
 "items": [{"tk": "spx", "label": "S&P500", "cause": "레짐 변화",
            "detail": "무엇이 언제 얼마나 어긋났고 어느 지표 탓인지 2~3문장",
            "suggest": "보완 제안 1~2문장 (제안일 뿐 자동 적용 안 함)"}]}
```

### Phase 4 — 업로드
`claudeCowork/SECURITY/nmr_deploy_key` 를 `$HOME`에 복사(chmod 600, /tmp 쓰기불가) 후:
```
scp -i $HOME/nmr_deploy_key 리뷰파일 ubuntu@161.33.190.254:/home/ubuntu/namoobi/data/db/stlead_review.json
```
Portfolio 탭 실전 성적 박스가 자동 표시한다. 코드 수정을 했다면 gitsync.sh로 커밋.

### 완료 보고
채점 수·이탈 자산·분류 결과를 2~3문장으로 요약. 이탈이 없으면 "이상 없음" 한 줄.
